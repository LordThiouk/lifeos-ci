### Ce que l’URL doit pointer
- Route web Laravel staging (pas d’API publique) :  
  `POST {STAGING}/{ADMIN_PREFIX}/drivers/verification-approve/{id}`  
  - `ADMIN_PREFIX` défaut = `admin` (env `ADMIN_PREFIX`)  
  - `{id}` = driver DB id du compte lane B lot = **900323** (workflow IDs staging)  
  - Exemple forme : `https://<host-staging>/admin/drivers/verification-approve/900323`
- **Attention** : la route est sous middleware `admin` (session web) et répond `back()` (302). Le harnais envoie `Authorization: Bearer …` + `dev-token`. Donc soit :
  - **A (recommandé)** : helper staging dédié e2e qui accepte Bearer + `dev-token`, appelle la même logique `dv=VERIFIED`, répond **200** ou **302** ; URL secrète = ce helper ;  
  - **B** : pointer la route admin telle quelle seulement si un bridge session/Bearer existe déjà (sinon HTTP 419/401 → FAIL HTTP code).

### Rôle admin staging
- Compte **admin** connecté (middleware `admin`). La route `verification-approve` n’a **pas** de `permission:` supplémentaire → tout admin authentifié suffit (pas besoin d’un rôle nommé au-delà d’admin).
- Cible : driver id **900323** (lot / lane b). ISC-22 / 22.1 = refresh KYC post-approve (marqueurs `lot-kyc-refresh` / `lot-rider-kyc-refresh`).

### Durée de vie du jeton
- Si helper Bearer : jeton **staging-only**, rotation courte recommandée (**≤ 7 jours**, révocable) ; jamais un secret prod.
- Session Laravel admin native : `SESSION_LIFETIME` défaut **120 min** — inadapté tel quel pour CI longue ; d’où le helper Bearer.
